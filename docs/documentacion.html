1. ¿Qué es este sistema?

Es una página web para el salón de belleza Gaby Salón y Spa. Tiene dos partes:

  • La parte pública: lo que ve cualquier persona que entra a la página. Muestra la información del salón (servicios, precios, galería de fotos, contacto) y permite reservar una cita por internet.
  • La parte de administración (panel): una zona privada, protegida con usuario y contraseña, donde el salón administra sus servicios, ve las reservas de las clientas, anota lo que se hace cada día y consulta reportes de ingresos.
En pocas palabras: las clientas usan la parte pública para informarse y reservar; el salón usa el panel privado para llevar el control de su negocio.

¿Para qué sirve tener todo esto conectado?

La gracia del sistema es que las partes están enlazadas: los servicios que carga el salón aparecen en la página y en el formulario de reservas; las reservas y los servicios realizados alimentan los reportes de ingresos. Todo trabaja junto y la información se guarda en la nube (internet), no en un cuaderno.

4. Cómo instalar y correr el programa (desde cero)

Estos pasos son para alguien que nunca ha corrido un programa. Seguílos en orden.

Paso 1 — Instalar Node.js

Node.js es el programa que permite ejecutar el proyecto. Sin él, nada funciona.

1. Entrá a https://nodejs.org
2. Descargá la versión que dice "LTS" (la recomendada).
3. Abrí el archivo descargado y seguí la instalación con "Siguiente / Continuar" hasta el final.

Paso 2 — Descargar el proyecto

El proyecto está guardado en internet (GitHub). Hay que traerlo a la computadora.

Opción fácil: entrá a https://github.com/JCortes23/GabySalaon, hacé clic en el botón verde "Code" y luego en "Download ZIP". Descomprimí (extraé) la carpeta en un lugar fácil de encontrar, por ejemplo el Escritorio.

Paso 3 — Abrir la carpeta en la "Terminal"

La Terminal es una ventana donde se escriben comandos. En Mac se llama "Terminal", en Windows "Símbolo del sistema" o "PowerShell".

1. Abrí la Terminal.
2. Escribí cd (con un espacio después) y arrastrá la carpeta del proyecto a la ventana; se pega la ruta sola. Presioná Enter.

Esto le dice a la Terminal: "trabajá dentro de esta carpeta".

Paso 4 — Instalar las piezas que necesita el proyecto

Escribí este comando y presioná Enter: 
npm install
Va a tardar 1–2 minutos descargando todo lo necesario. Es normal ver muchos mensajes.

Paso 5 — Conectar la base de datos

El proyecto necesita unas "llaves" secretas para conectarse a Firebase. Se guardan en un archivo llamado .env.local. Cómo obtener esas llaves se explica en el capítulo 5.

1. En la carpeta del proyecto hay un archivo de ejemplo: .env.local.example.
2. Hacé una copia y renombrala como .env.local.
3. Adentro, pegá las llaves de tu proyecto de Firebase.
Importante: el archivo .env.local contiene datos privados y por eso nunca se sube a internet. Cada computadora tiene el suyo.

Paso 6 — Correr el programa

Escribí este comando y presioná Enter: 
npm run dev
Cuando aparezca el mensaje "Ready", el programa ya está corriendo.

Paso 7 — Ver la página

Abrí el navegador y entrá a: http://localhost:3000
Para apagar el programa, volvé a la Terminal y presioná Ctrl + C. Para volver a encenderlo, repetí el Paso 6.

5. Configuración de Firebase (paso a paso)

Firebase es el servicio de Google que usa el proyecto para dos cosas: el inicio de sesión (Authentication) y la base de datos (Firestore). Hay que configurarlo una sola vez. Todo es gratuito.

Paso 1 — Crear el proyecto

1. Entrá a https://console.firebase.google.com e iniciá sesión con una cuenta de Google.
2. Clic en "Crear un proyecto", ponele un nombre (ej: gabysalon) y aceptá.
3. Podés desactivar Google Analytics (no hace falta). Clic en "Crear proyecto".

Paso 2 — Registrar la aplicación web y copiar las llaves

1. En la pantalla principal del proyecto, clic en el ícono web </>.
2. Poné un apodo y registrá la app.
3. Firebase muestra un bloque llamado firebaseConfig con varias llaves (apiKey, projectId, etc.). Esas llaves son las que van en el archivo .env.local (ver capítulo 4, Paso 5).

Paso 3 — Activar el inicio de sesión

1. En el menú, entrá a Authentication → Comenzar.
2. En "Sign-in method", activá "Correo electrónico/contraseña" y guardá.
3. En la pestaña Users, creá un usuario administrador con su correo y contraseña. Ese es el usuario para entrar al panel.

Paso 4 — Crear la base de datos

1. En el menú, entrá a Firestore Database → Crear base de datos.
2. Elegí una ubicación cercana (ej: nam5 / us-central) — no se puede cambiar después.
3. Elegí "Iniciar en modo de producción" y creá.

Paso 5 — Publicar las reglas de seguridad

1. En Firestore, entrá a la pestaña Reglas (Rules).
2. Copiá el contenido del archivo firestore.rules del proyecto y pegalo ahí.
3. Clic en Publicar. (Qué hacen esas reglas se explica en el capítulo 16.)

Paso 6 — Cargar los servicios iniciales

Iniciá sesión en /admin, entrá al módulo Servicios y hacé clic en "Importar servicios actuales". Esto copia los servicios de ejemplo a la base de datos de una sola vez.

6. Cómo usar el sistema

Como clienta (parte pública)

  1. Entrá a http://localhost:3000.
  2. Se ve la información del salón: servicios con precios, galería, testimonios y contacto.
  3. Para reservar, hacé clic en "Reservar" (arriba) o entrá a http://localhost:3000/reservar.
  4. Elegí el servicio, la fecha, la hora, escribí tu nombre y WhatsApp, y confirmá.

Como administrador (panel privado)

  1. Entrá a http://localhost:3000/admin (o hacé clic en el candado del menú).
  2. Iniciá sesión con el correo y contraseña creados en Firebase.
  3. Vas a ver 4 módulos: Servicios, Reservas, Registro diario y Reportes.

8. La base de datos (Firebase / Firestore)

La información se guarda en Cloud Firestore, la base de datos de Google. Firestore organiza los datos en colecciones (grupos) y cada dato es un documento (una ficha con campos).

Este sistema usa 4 colecciones:

Colección services (servicios)

CampoQué guarda
categoryLa categoría (Cabello, Uñas, Spa & Estética).
nameEl nombre del servicio.
descLa descripción.
priceEl precio en colones.
orderEl orden en que aparece.
activeSi está activo (true) o archivado (false).

Colección reservations (reservas)

CampoQué guarda
date / timeLa fecha y hora de la cita.
serviceName / category / priceCopia del servicio elegido (para no perder el dato si cambia después).
customerName / customerPhoneNombre y WhatsApp de la clienta.
statusEstado: pendiente, confirmada, completada o cancelada.
slotIdIdentificador de la franja horaria (para controlar los cupos).

Colección slots (cupos por hora)

CampoQué guarda
date / timeLa hora exacta.
countCuántas reservas ocupan esa hora (para no pasarse de la capacidad).

Colección records (registro diario)

CampoQué guarda
dateEl día en que se realizó el servicio.
serviceName / category / priceCopia del servicio realizado.
quantityCuántas veces se hizo.
noteUna nota opcional.

10. Módulo 2 — Inicio de sesión de administradores

Archivos src/app/admin/login/page.tsx · src/lib/firebase.ts

Protege el panel privado. Solo quien tenga usuario y contraseña puede entrar.

Cómo funciona

  1. La persona escribe su correo y contraseña.
  2. El sistema le pregunta a Firebase Authentication si esos datos son correctos.
  3. Si son correctos, la lleva al panel. Si no, muestra un mensaje de error.
  4. Todas las pantallas del panel verifican que haya una sesión activa; si no, devuelven al inicio de sesión automáticamente.
Las contraseñas no se guardan en el código ni en la base de datos del proyecto: las administra Firebase de forma segura.

11. Módulo 3 — Servicios

Archivos src/app/admin/services/page.tsx · src/lib/services.ts

Permite administrar la lista de servicios del salón.

Qué se puede hacer

  • Crear un servicio (categoría, título, descripción y precio).
  • Editar un servicio existente.
  • Archivar un servicio (dejar de mostrarlo).
  • Restaurar un servicio archivado.
  • Importar los servicios de ejemplo de una sola vez (botón "Importar servicios actuales").

Borrado lógico (concepto clave)

Cuando se "elimina" un servicio, en realidad no se borra de la base de datos: solo se marca como archivado (active = false) y deja de mostrarse. Esto se hace así para no perder información que los reportes puedan necesitar en el futuro.

12. Módulo 4 — Reservas

Archivos parte pública src/app/reservar/page.tsx · panel src/app/admin/reservations/page.tsx · lógica src/lib/booking.ts

Del lado de la clienta

  1. Elige un servicio, una fecha y una hora disponible.
  2. El sistema muestra las horas según el horario del salón (definido en site.ts): Lunes a Viernes de 8:00 a 18:00, Sábado de 8:00 a 16:00, Domingo cerrado.
  3. Las horas que ya están llenas aparecen tachadas y no se pueden elegir.
  4. Al confirmar, la reserva queda como "pendiente".

Control de cupos (cómo se evita la doble reserva)

Cada hora tiene una capacidad (por defecto 2 personas a la vez, configurable en site.ts). El sistema lleva un contador por hora en la colección slots: 

1) Revisa cuántos cupos hay ocupados en esa hora
2) Si ya está llena, avisa que no hay disponibilidad
3) Guarda la reserva
4) Suma 1 al contador de esa hora

Del lado del administrador

El salón ve las reservas por día y puede cambiar su estado:

EstadoSignificado
PendienteRecién llegó, falta confirmarla.
ConfirmadaEl salón la aceptó.
CompletadaEl servicio ya se realizó.
CanceladaSe anuló (esto libera el cupo de esa hora).

13. Módulo 5 — Registro diario

Archivos src/app/admin/records/page.tsx · src/lib/records.ts

Es la bitácora del día: el salón anota cada servicio que realiza.

Cómo funciona

  1. Se elige la fecha, el servicio, la cantidad y (opcional) una nota.
  2. Al guardar, el sistema anota una copia del servicio con su precio de ese momento.
  3. La pantalla muestra el total de servicios y el total en colones del día.
Por qué guarda una copia del precio: así, si mañana se cambia el precio de un servicio, los registros de días anteriores siguen mostrando el precio real que se cobró ese día. Esto hace que los reportes sean confiables.

14. Módulo 6 — Reportes

Archivos src/app/admin/reports/page.tsx

Muestra un resumen de lo que se registró en el módulo anterior.

Qué muestra

  • Selector de período: Hoy, Últimos 7 días, Este mes, Mes anterior o un rango personalizado.
  • Ingresos totales del período.
  • Cantidad de servicios realizados.
  • Ingresos por categoría: una barra por cada categoría con su monto y porcentaje.

Cómo hace los cálculos

El sistema pide a la base de datos todos los registros del período elegido y los suma con operaciones simples (recorre la lista, va sumando los ingresos y agrupando por categoría). No hay nada guardado "pre-calculado": los números se arman en el momento con la información real.

15. Flujo completo del sistema (ejemplo de principio a fin)

Para entender cómo se conecta todo, sigamos el recorrido de una cita real, desde que la clienta reserva hasta que aparece en los reportes:

El salón carga sus servicios. Desde el módulo de Servicios, el admin crea (o importa) los servicios con sus precios. Se guardan en la colección services.
Los servicios aparecen en la web. La página pública y el formulario de reservas leen la colección services y muestran los servicios activos.
La clienta reserva. Entra a "Reservar", elige "Corte & Peinado" para el viernes a las 14:00, deja su nombre y WhatsApp. Se crea un documento en reservations con estado pendiente y se suma 1 al contador de esa hora en slots.
El admin ve la reserva. En el módulo de Reservas aparece la cita del viernes como "pendiente". El admin la confirma.
El día de la cita, se completa. Cuando la clienta llega y se atiende, el admin marca la reserva como completada.
Se anota en el registro diario. El admin registra el servicio realizado ese día en el módulo de Registro diario. Se guarda en records con una copia del precio.
Aparece en los reportes. En el módulo de Reportes, ese servicio ya suma a los ingresos del día, de la semana y del mes, y al total de la categoría "Cabello".
La idea central: cada módulo aporta datos que otro módulo aprovecha. Los servicios alimentan las reservas y el registro; el registro alimenta los reportes. Todo conectado a través de la base de datos.

16. Seguridad (reglas de la base de datos)

Archivo firestore.rules

Las reglas definen quién puede leer y escribir cada colección. Se configuran en la consola de Firebase. Este es el resumen:

ColecciónQuién puede leerQuién puede escribir
servicesCualquiera (la web muestra los servicios)Solo administradores con sesión
recordsSolo administradoresSolo administradores
reservationsSolo administradoresLas clientas pueden crear; editar solo admins
slotsCualquiera (solo es un número de cupos)Cualquiera (al reservar)
Los datos privados de las clientas (nombre, teléfono) no se muestran en la parte pública: solo los administradores los pueden ver.

17. Preguntas típicas de la exposición (con respuestas)

Estas son preguntas que suelen hacer al presentar un proyecto así. Estudiá las respuestas para defenderlo con seguridad.

1. ¿Por qué elegiste Next.js y React?

Porque permiten construir páginas modernas y rápidas dividiendo la interfaz en componentes reutilizables. Son de las herramientas más usadas hoy, gratuitas y con mucha documentación.

2. ¿Por qué usaste Firebase y no una base de datos como MySQL?

Firebase incluye la base de datos y el inicio de sesión ya listos, sin tener que programar ni pagar un servidor propio. Para un proyecto de este tamaño simplifica mucho el trabajo y funciona en la nube.

3. ¿Qué es un componente?

Una pieza reutilizable de la interfaz, como un botón o una tarjeta. Se programa una vez y se usa en varios lugares. Por ejemplo, el botón de WhatsApp es un componente que aparece en varias secciones.

4. ¿Cómo funciona el inicio de sesión? ¿Dónde se guardan las contraseñas?

El login usa Firebase Authentication. Las contraseñas no están en mi código ni en mi base de datos: las guarda y verifica Firebase de forma segura. El sistema solo pregunta "¿este correo y contraseña son válidos?".

5. ¿Qué es el "borrado lógico" y por qué lo usaste?

En lugar de borrar un servicio de verdad, lo marco como archivado (un campo active en falso). Así deja de mostrarse pero no se pierde la información, que puede ser necesaria para los reportes históricos.

6. ¿Cómo evitás que dos clientas reserven el mismo cupo?

Cada hora tiene una capacidad y un contador en la colección slots. Antes de guardar una reserva, el sistema revisa cuántos cupos hay ocupados; si ya está lleno, no permite reservar. Al reservar, suma 1 al contador.

7. ¿Por qué guardás una copia del precio en las reservas y registros?

Para que los reportes históricos sean correctos. Si más adelante cambio el precio de un servicio, los registros viejos siguen mostrando el precio real que se cobró ese día.

8. ¿Qué son las reglas de Firestore?

Son las que definen quién puede leer y escribir cada colección. Por ejemplo, cualquiera puede ver los servicios, pero solo un administrador con sesión puede modificarlos, y los datos de las clientas solo los ve el admin.

9. ¿Las clientas necesitan crear una cuenta para reservar?

No. Reservan como invitadas, solo con su nombre y WhatsApp. Esto reduce la fricción y aumenta la probabilidad de que reserven.

10. ¿Cómo se conectan los módulos entre sí?

A través de la base de datos. Los servicios alimentan las reservas y el registro diario; el registro diario alimenta los reportes. (Ver el capítulo 15, "Flujo completo del sistema".)

11. ¿Qué mejorarías si tuvieras más tiempo?

Agregar notificaciones automáticas al salón cuando llega una reserva, protección anti-spam en el formulario (reCAPTCHA), y publicar el sitio en internet para uso real.

12. ¿La información se pierde si apago la computadora?

No. Los datos están en la nube (Firebase), no en la computadora. Apagar el programa solo detiene la página; la información sigue guardada.

18. Problemas comunes y soluciones

ProblemaSolución
Al correr npm run dev dice "command not found". No está instalado Node.js. Repetí el Paso 1 del capítulo 4.
La página dice "No se pudieron cargar los servicios". La base de datos (Firestore) no está creada, o se acaba de crear y tarda unos segundos. Esperá un momento y recargá.
El inicio de sesión no funciona. Verificá que el usuario exista en Firebase (Authentication → Users) y que el método "Correo/contraseña" esté activado.
Los servicios aparecen vacíos. Entrá al módulo de Servicios y usá el botón "Importar servicios actuales".
La página no abre en el navegador. Revisá que la Terminal muestre "Ready" y que estés entrando a http://localhost:3000.
Cambié el horario o la capacidad y no se refleja. Esos valores están en src/content/site.ts (sección booking). Guardá el archivo y recargá la página.
